# Changelog

All notable changes to go-topology-suite will be documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

> **Semver exception.** This release knowingly contains breaking API changes without a `/v2` module-path bump: v1.0.0 was tagged days before these fixes with zero external adopters, and carrying the footguns below (mutable-buffer `FlatCoords`, XY-only constructors, a three-way-inconsistent nil contract) into real adoption was judged worse than a one-time, fully documented break. The apidiff against v1.0.0 is limited to exactly the entries marked "breaking" here. The v1 stability promise applies unqualified from this release forward.

### Changed (breaking)

- **`buffer.Buffer` distance on geographic (lon/lat) input is now METRES, not planar degrees.** `Buffer`, `VariableBuffer`, and `VariableBufferInterpolated` project a geographic input into a local metric frame, buffer there, and project back (see Added). Previously the buffer ran directly on degrees and the package doc declared the output "nonsense" — this is a bug-fix-grade behaviour change. Callers who genuinely want degree-unit buffers must strip the CRS with `geom.WithCRS(g, nil)`. `buffer.OffsetCurve` is unaffected and stays planar.
- **`overlay` operations on geographic input now compute in a local projected frame, not in degree space.** `Intersection`, `Union`, `Difference`, `SymmetricDifference`, and `UnaryUnion` (and the `EnhancedPrecision*` wrappers) project geographic operands into a shared local metric frame and project the result back (see Added). Results are geometrically correct in a true plane instead of the areal/topological distortions of planar-on-degrees math. Projected-CRS and CRS-less inputs are byte-identical to before. To force the old planar-degree behaviour, strip the CRS with `geom.WithCRS(g, nil)`.
- **`geom.NewLineString`, `NewLinearRing`, `NewPolygon`, and `NewMultiPoint` are now generic over the coordinate element type** (`[C geom.Coord]`, the closed union `XY | XYZ | XYM | XYZM`). The layout is inferred from the element type, so a single call constructs Z/M geometries — `geom.NewLineString(crs, []geom.XYZ{...})` — instead of the twelve named variants that would otherwise be needed. Existing `[]geom.XY` call sites compile unchanged. The one incompatibility: sites that passed an untyped `nil` can no longer infer the type parameter; use the layout-carrying `NewEmpty*` constructor (or a typed nil such as `[]geom.XY(nil)`) instead.
- **`geom.NewLinearRingFlat` removed.** The clone-variant was inconsistent with the `*Owned` family. Its sole caller — the WKT decoder — now uses `geom.NewLinearRingOwned`, which has identical semantics for the nil buffer it passed.
- **`FlatCoords()` removed from every geometry type; read coordinates with `AppendFlatCoords(dst []float64) []float64`.** `FlatCoords` handed out the geometry's internal, mutable coordinate buffer — mutating it silently corrupted the lazily-cached envelope. The new append-into accessor (matching `Polygon.RingInto`) copies into a caller-owned slice; pass `nil` for a fresh one. It is the supported way for external code to read the Z/M ordinates of non-Point vertices, which the typed accessors otherwise project away to XY. In-module encoders (`wkb`, `wkt`, `geojson`, `predicate`) read the buffer zero-copy through the new internal `flatref` bridge, so encoder output is byte-identical.
- **Unified nil-geometry contract (behavioural change; see `gts.ErrNilGeometry` under Added).** Every exported operation that takes a geometry now handles a nil operand consistently, replacing a three-way-inconsistent mix of panics, silent "empty" answers, and mis-scoped sentinels. Notable deltas:
  - `gts.Transform(nil, target)` returned `(nil, nil)` — silently swallowing the caller's mistake — and now returns `(nil, ErrNilGeometry)`.
  - `overlay.UnaryUnion(nil)` returned `(nil, nil)` and now returns `(nil, ErrNilGeometry)`. The binary overlay ops (`Intersection`/`Union`/`Difference`/`SymmetricDifference` and their `EnhancedPrecision*` wrappers) and every binary `predicate` (`Intersects`/`Contains`/`Covers`/`Crosses`/`Equals`/`Overlaps`/`Touches`/`Relate`/… and the delegating `Disjoint`/`Within`/`CoveredBy`) now return `ErrNilGeometry` for a nil operand, checked before the CRS comparison, via shared guards (`overlay.requireSameCRS`, `predicate.guardBinary`).
  - `buffer.Buffer(nil, …)` returned the mis-scoped `ErrInvalidGeometry`; it now returns `ErrNilGeometry`. `buffer.VariableBuffer`/`VariableBufferInterpolated` likewise (nil case only; the empty-line and bad-distance cases keep `ErrInvalidGeometry`).
  - `measure.Distance(nil, …)` panicked on `a.CRS()`; it now returns `(NaN, ErrNilGeometry)`. `measure.Centroid(nil)` panicked; it now returns a non-nil empty `*geom.Point`. The Hausdorff/Fréchet functions treated nil as `NaN` and now treat it as empty (both-nil → 0, one-nil → +Inf), matching their empty-input semantics.
  - Error-returning hull/simplify/validate/precision entry points (`hull.ConcaveHull`/`ConcaveHullByLengthRatio`, `simplify.PolygonHull`/`PolygonHullByAreaDelta`, `validate.MakeValid`, `precision.CommonBitsOp`) now return `ErrNilGeometry` on nil (previously `errors.New`, `ErrEmpty`, or a passed-through result). Total operations (`hull.ConvexHull`, `simplify.Simplify`/`TopologyPreserving`/`Visvalingam`, `validate.Fix`, `precision.Reduce`/`SnapTo`/…, `densify.Densify`, `buffer.OffsetCurve`, `geom.Edit`/`WithCRS`) return nil for nil, and the slice-taking `linemerge.Merge`/`polygonize.Polygonize`/`dissolve.Lines` skip nil elements — several of these were already compliant and are now locked in with tests.

### Added

- **Automatic geographic-CRS handling in `overlay` and `buffer` via a projection round trip.** `overlay.Intersection`/`Union`/`Difference`/`SymmetricDifference`/`UnaryUnion` and `buffer.Buffer`/`VariableBuffer`/`VariableBufferInterpolated` now detect a geographic (lon/lat) input, project it into an ad-hoc local metric frame centered on its envelope (Transverse Mercator, or a polar Lambert Azimuthal Equal-Area beyond ±84° latitude), run the existing planar engine there, and project the result back — the PostGIS `geography`-type precedent. The result keeps the input's CRS pointer. A CRS mismatch is still rejected first (this is local frame selection, not reprojection between user CRSes); to opt out and force planar-degree math, strip the CRS with `geom.WithCRS(g, nil)`. `buffer.OffsetCurve` is the deliberate exception and stays planar. New internal package `internal/geoframe` implements the frame selection and round trip.
- **`gts.ErrGeographicExtent`** — a new sentinel returned by the geographic overlay/buffer paths when the input is too large for the automatic local-projection frame: its envelope spans more than 180° of longitude, or its physical extent exceeds the ~1,000,000 m limit beyond which the projection scale error grows past tolerance. Reproject explicitly with `gts.Transform`. Errors wrapping it match with `errors.Is`.
- **`crs.(*CRS).Definition() *crs.Definition`** — nil-safe accessor for the transform Definition (datum, axis order, projection) attached at construction, or nil for identity-only CRSes. Exposes the source datum that the geographic round trip needs to build a same-datum frame (a pure projection, no datum shift).
- **`geom.NewMultiPointOwned(layout, crs, flat)`** — donate-ownership MultiPoint constructor that completes the `*Owned` family (parallels `NewLineStringOwned`). Format decoders use it to build MultiPoints at full stride.
- **`gts.ErrNilGeometry`** — a new sentinel for the nil-geometry operand case, distinct from `ErrInvalidGeometry` (which stays scoped to invariant violations of real, non-nil geometries). It anchors a single module-wide contract, documented beside the sentinel in `errors.go`: error-returning operations return `ErrNilGeometry` on any nil operand (checked before CRS/empty checks); non-error total operations treat nil as empty (geometry-returning → interface nil, scalar → the empty-input value, ok-returning → zero+false, concrete-pointer → an empty concrete value, never a typed-nil pointer); slice-taking operations skip nil elements.
- **`overlay.UnaryUnion` bounds its cascaded union tree across up to `GOMAXPROCS-1` extra goroutines — the library's first internal goroutines.** `cascadedBinaryUnion` recurses on the two halves of an immutable, spatially-sorted slice; the halves are provably independent (disjoint index ranges), so on large inputs the left half is now spawned onto its own goroutine while the right half runs on the caller's, joined in the same fixed order the sequential code used. Fan-out is bounded by a package-level semaphore sized to `GOMAXPROCS(0)-1` and shared across all concurrent `UnaryUnion` calls in the process (not one budget per call), acquired non-blockingly: a call spawns only when a token is free *and* the subtree spans at least `parallelUnionThreshold` (64) input geometries, otherwise it runs the original fully-sequential path with zero goroutine overhead — on a single-`GOMAXPROCS` process the semaphore has zero capacity and every call stays sequential. Results are byte-identical to sequential execution regardless of scheduling: the join always combines `(leftResult, rightResult)` in the same order, and of the two halves' errors the left's is deterministically preferred. A panic in the spawned goroutine is recovered and re-raised on the caller's goroutine rather than silently killing the process. Every structure the two halves touch concurrently was already concurrency-safe and race-tested before this change (`kernel/planar`'s `orientCache` `RWMutex`, `geom/base.go`'s atomic envelope caches, the `xybuf` `sync.Pool`), so no new synchronization was needed beyond the join itself. On a 32-thread machine, `BenchmarkUnaryUnion/grid/n=256` (`overlay` package, 256-quad field) drops from 6.95ms to 3.81ms/op (-45%, 1.83×); `n=64` drops 19% and `n=16` (below the threshold) is unchanged (`~`, p=1.000) — confirming the below-threshold path is genuinely zero-overhead. The bench-module macro workload (1,000 overlapping quads) shows a smaller but still significant gain, ~25% (1.34×), since most of its individual leaf unions are cheap enough that fork/join and GC overhead eat into the benefit more than on the larger-polygon grid fixture. Allocations/bytes are flat (+0.5%/+0.06%, the goroutine and channel bookkeeping). Verified with a determinism test that runs `UnaryUnion` on a 529-polygon overlapping-grid fixture through both the forced-sequential and forced-parallel code paths (`parallelUnionThreshold` is a var for this purpose) and asserts `wkb.Marshal` byte-equality, plus `-race -count=5` on `overlay` and a full `-race ./...` pass. JTS conformance held at 8942/8951. See the `overlay` package doc's new Concurrency section and the README Design notes for the caller-visible contract: every other operation remains single-goroutine.

- **`geom.UnwrapLinearRing(g geom.Geometry) geom.Geometry`** — normalizes a `*LinearRing` to its `AsLineString` view and returns every other Geometry unchanged (nil stays nil). Call it before type-switching over a Geometry unless the switch handles `*LinearRing` explicitly, so a ring does not silently fall through the default case. It replaces the private per-package copies that `predicate` and `overlay` carried.

### Removed

- **GEOS/PostGIS cross-implementation conformance stubs** (`bench/conformance/geos_impl.go`, `bench/conformance/postgis_impl.go`) and their `cgo`/`postgis` build-tag documentation. The stubs were never wired to a real backend — `newDefaultImpls()` only ever compared go-topology-suite against simplefeatures, and no CI job used the tags. Bench-module-only cleanup; not part of the v1 public API surface. Drops the `github.com/twpayne/go-geos` dev-only dependency from `bench/`.

### Fixed

- **`validate.Validate(nil)` panicked with a nil-pointer dereference** (it called `g.Layout()` on the nil interface before any guard). It now returns `gts.ErrNilGeometry` — "no geometry" is reported distinctly from a real geometry that violates an invariant (which still yields `*ValidationError`).
- **`MULTIPOINT` silently dropped Z and M ordinates on decode in all three formats.** The WKB, WKT, and GeoJSON decoders truncated every MultiPoint member to XY, because the old `NewMultiPoint` only accepted `[]geom.XY`. They now route full-stride coordinates through `geom.NewMultiPointOwned`, so `MULTIPOINT Z` / `M` / `ZM` round-trips preserve every ordinate.
- **`crs.Equal` now recognises structurally identical ad-hoc CRSes.** Two CRSes built with `crs.NewWithDefinition` that carry no authority code and no WKT2 text — but have the same `Kind` and a deep-equal `*Definition` (datum, axis order, projection) — now compare equal instead of only by pointer. Comparison is layered in four tiers: pointer identity, authority code, WKT2 text, then this structural fallback. Definition remains payload rather than identity for authority-identified CRSes, so `crs.WGS84` still equals its `epsg`-registry counterpart; definition-less ad-hoc CRSes remain pointer-equal-only. Custom `crs.Projection` implementations must be `reflect.DeepEqual`-comparable value types to participate in the structural tier.
- **The `Geometry` interface no longer claims universal envelope caching.** The `Envelope` doc previously stated the result is always "cached after the first call"; in fact `Point.Envelope` computes inline (the single-coordinate math is cheaper than the cache allocation). The doc now says implementations either cache after the first call (lock-free via an atomic pointer) or compute inline when that is cheaper — either way repeated calls are cheap and concurrency-safe.
- **Package docs acknowledge `LinearRing` as an eighth concrete `Geometry` type.** `geom`'s package doc, the `Type` doc, and the `LinearRing` type doc previously described only the "seven OGC Simple Features types", making `*LinearRing` a surprise in a Geometry type switch. They now call it out explicitly and point at `UnwrapLinearRing` for normalizing rings away.
- **`internal/overlayng`'s touching-ring canonicalization check was O(n²) in the output polygon count.** `needsCanonicalize` ran `multiPolygonsTouch` after every overlay op with two or more output polygons, and its all-pairs loop re-fetched `polys[j].Ring(0)` (an allocating copy, `geom.Polygon.RingInto`) and rebuilt `j`'s vertex-set map on every `(i, j)` iteration instead of once per polygon — for a fragment-heavy overlay (e.g. a jagged-star intersection producing thousands of output polygons) this dominated both CPU and allocations, with the op scaling worse than cubically in fragment count. Rings, vertex sets, and envelopes are now materialised once per polygon up front, and pairs whose (cached) envelopes don't intersect skip the segment tests entirely — touching rings always have intersecting envelopes, so output is byte-identical. `BenchmarkIntersection/star/n=1024` and `BenchmarkDifference/star/n=1024` drop from ~2.5s to ~0.25s (-90%) and from ~5.75M/6.73M allocs to ~287k/291k (-95%).
- **`index.RTree.Insert` was O(n) per call — O(n²) for n sequential inserts.** After every single-item insert, `adjustEnvelopes` unconditionally called `recomputeEnvelopeRecursive`, a full deep walk of the entire tree, even though the doc comment on that function said it was "only used after bulk rebuilds." Since inserted envelopes only ever grow the tree (they can't shrink it), the fix expands ancestor envelopes along just the root-to-leaf descent path instead of recomputing the whole tree; on the rarer split path, where an envelope legitimately can shrink, affected nodes are still recomputed, but shallowly and only along that same path (also removing a second latent full-tree walk, `findParent`, now replaced by the recorded descent path). This is the dominant cost in `buffer`'s snap-rounding noder, which inserts every vertex into an R-tree one at a time: `BenchmarkRTreeInsertSequential/n=10000` drops from ~273ms to ~16ms/op (-94%), and `BenchmarkBuffer/star/n=1024` drops from ~2.17s to ~0.15s/op (-93%), with allocations/op unchanged (a reused per-tree scratch buffer avoids a new slice on every insert).
- **`internal/overlayng`'s output-polygon assembly classified ring nesting by brute force — O(rings²) ray-casts.** `AssembleOutputPolygons` computed each ring's nesting depth by testing its representative point against *every other ring* with `geomath.PointInRing`, and repeated the same all-pairs shape for hole-to-outer parent assignment — O(R²·L) ray-casts that dominated fragment-heavy overlays (61% of CPU on a jagged-star intersection producing ~3,300 output rings). Ring envelopes are now computed once up front and STR-bulk-loaded into two `index.RTree`s (ring envelopes for point-containment queries; representative points for ring-coverage queries), and `PointInRing` runs only on envelope-filtered candidates. Envelope containment is a necessary condition for `PointInRing`, so this is pure candidate pruning — depths, parent selection, and output are byte-identical (hole candidates are re-sorted to the brute-force scan order), and inputs under 16 rings keep the original brute-force path to skip index overhead. The `overlay` ops and `buffer`'s polygonizer share the fix. `BenchmarkIntersection/star/n=1024` drops from ~256ms to ~109ms/op (-57%), `BenchmarkDifference/star/n=1024` from ~251ms to ~87ms/op (-65%), and `BenchmarkUnaryUnion/grid` sizes improve 37-39%, with allocations essentially unchanged (≤0.4%).
- **`internal/overlayng`'s touching-ring detection still compared every output polygon against every other — O(P²) envelope pairs.** After the earlier per-pair-copy fix, `multiPolygonsTouch` kept a brute-force all-pairs double loop over the output polygons (5.5M envelope pairs at ~3,300 fragments on the jagged-star intersection — 21% of overlay CPU), and its per-polygon vertex sets were `map[geom.XY]struct{}`s hashed on 16-byte float pairs. The outer-ring envelopes are now STR-bulk-loaded into an `index.RTree` and each polygon tests only the envelope-intersecting candidates the index returns — the same envelope guard the brute-force loop applied, so this is pure pair pruning and the returned decision is unchanged (outputs below 16 polygons keep the plain loop to skip index overhead). The build-once-probe-many vertex sets are now single flat `[]geom.XY` slices sorted by the DCEL's NaN-safe `vertexKey` (Float64bits) packing and probed by binary search; the genuinely interleaved insert+lookup maps (`ringHasRepeatedInteriorVertex`, `splitSelfTouchingRing`, and the shared-edge owner map) stay maps but re-keyed from `geom.XY`/coordinate pairs to the cheaper packed `vertexKey` — consistent with how the DCEL itself already keys vertices and edges. `BenchmarkIntersection/star/n=1024` drops from ~109ms to ~91ms/op (-16%), `BenchmarkUnion/star/n=1024` from ~256ms to ~197ms (-23%), `BenchmarkDifference/star/n=1024` from ~87ms to ~75ms (-14%), with allocations essentially unchanged (geomean -0.2%).
- **`measure.Distance` re-allocated a polygon's entire ring on every vertex it visited.** `geometryDistance`'s vertex-segment loops nest `visitSegments(b, ...)` inside `visitVertices(a, ...)` (and vice versa), so a polygon operand's rings were re-copied by `geom.Polygon.Ring` (an allocating `RingInto(nil, ...)`) once per vertex of the *other* operand — O(vertices × ring length) allocation for a single `Distance` call. `distance_op.go`'s `polygonContains` (the areal-containment fast path `geometryDistance` tries first) had the identical pattern: it re-fetched the shell and every hole ring inside its `visitVertices(other, ...)` closure. `visitVertices`/`visitSegments` now walk polygon rings via the existing non-allocating `Polygon.RingLen`/`RingVertex` accessors instead of materializing a slice, and `polygonContains` hoists its shell/hole rings out of the per-vertex closure to fetch each once. Both changes are shared helpers, so `Length`, `DiscreteHausdorff`/`OrientedHausdorff`, and `IndexedFacetDistance` get the same fix for free. Results are bit-identical (rings don't change mid-call). `BenchmarkDistance/{disjoint,near}/n=1024` allocations drop from ~113MB/6170 allocs to ~36KB/3 allocs per op (-99.97%), with a 14-18% time reduction.
- **`internal/relateng`'s node-snapping scanned the entire node map for every intersection point — O(nodes²) per relate call.** `TopologyComputer.snapNodePt` looked for an existing node within `nodeSnapTol` (1e-12) of a new intersection point by iterating `for k := range tc.nodeMap`, so `RelateCold` on a 1024-vertex polygon pair spent 53.6% of CPU in this scan alone (`maps.(*Iter).Next` was 28.6% flat). A secondary grid index (`nodeIndex map[gridKey][]geom.XY`, cell size `nodeSnapTol`, same bucketing pattern as `internal/snap.HotPixelSet`) is now maintained alongside `nodeMap`; `snapNodePt` probes only the candidate's 3x3 cell neighbourhood — sufficient because a coordinate within the tolerance box can cross at most one cell boundary per axis — turning the scan into an O(1)-expected lookup. **Determinism note:** the tolerance test only guarantees newly-inserted keys aren't within tolerance of an *existing* key, not that all key pairs are more than `2×nodeSnapTol` apart, so more than one existing node could already fall within tolerance of a new point (e.g. keys at `x=0` and `x=1.5e-12` are each fine on insertion, but a later point at `x=0.75e-12` is within tolerance of both). The old full-scan implementation resolved such ties via Go's randomised map-iteration order — i.e. it was silently nondeterministic across runs, though the sub-2e-12 clustering needed to trigger it is exceedingly rare in practice. The rewrite picks deterministically: nearest candidate by Chebyshev distance, ties broken by lexicographic `(X, Y)` order. The single-candidate case (the overwhelming majority) is unchanged. `BenchmarkRelateCold/n=1024` drops from ~7.9ms to ~2.75ms/op (-65%), `BenchmarkIntersectsCold/n=1024` the same (shared code path), with a small memory increase (+8-10% B/op, +4% allocs/op) for the new index. JTS conformance held at 8942/8951.
- **`internal/overlayng`'s DCEL construction individually heap-allocated every `Vertex`/`HalfEdge`/`Face` record (38% of alloc_space on a jagged-star intersection), and its `next`-pointer wiring relocated each half-edge's twin by linearly scanning the destination vertex's `Out` list — O(E·avg-degree) — using two `math.Atan2` calls per edge solely to establish a sort order.** `buildDCELCore` now carves records from three arena slabs (`vertBacking`/`edgeBacking`/`faceBacking`) and takes `&backing[len-1]` after `append` instead of a per-record `&T{}`. Each slab is pre-sized to a typical-case estimate, not the worst-case bound: vertices to the segment count n (noded input is overwhelmingly closed rings/chains where each endpoint is shared by two segments; the 2n hard bound is only approached by fields of disjoint segments), half-edges to 2n (exactly 2 per unique segment — both the hard bound and the typical count), and faces — sized lazily in `traceFaceCycles`, which runs after construction — to Euler's formula `E−V+2` over the actual vertex/edge counts. Rare overflow past a slab's capacity falls back to an individual per-record heap allocation, so the arenas are never reallocated and pointer stability is structural: `append` only runs while `len < cap`. That invariant matters because downstream consumers compare these pointers for identity (`map[*HalfEdge]`/`map[*Vertex]`/`map[*Face]` in `extract_lineal.go`, `result.go`, `classify.go`, and the union-find in `buffer/polygonize.go`) — a silently reallocated slab would orphan every previously-taken pointer. (A first cut sized all three slabs to the 2n worst case; the unused-memory zeroing cost regressed cascaded `UnaryUnion` 3-6% and raised B/op ~14%, so the estimates were tightened with the overflow fallback instead.) The `next`-pointer scan is now O(1): each half-edge records its position (`outIdx`) in its origin vertex's angularly-sorted `Out` slice right after that sort runs, so wiring `e.next` reads `e.Twin.outIdx` directly instead of re-scanning `t.Out`. The two `Atan2` calls per edge are replaced by a monotonic pseudo-angle (`pseudoAngle`, the standard 2-branch octant formula) that is order-isomorphic to `Atan2` on the same `(-π,π]` domain — including the `dx<0`/`dy==±0` branch-cut boundary, matched via `math.Signbit` rather than `dy<0` — since the `angle` field is read only by the CCW sort. A redundant `vertexKey` re-hash of each edge's already-looked-up endpoints was also dropped. `buffer.Buffer` shares all of this via `BuildDepthDCEL`. Outputs are byte-identical (the sort and next-wiring rule are unchanged, just reordered/short-circuited); JTS conformance held at 8942/8951. Allocations drop 23-36%: `BenchmarkIntersection/star/n=1024` -31%, `BenchmarkUnion/star/n=1024` -32%, `BenchmarkDifference/star/n=1024` -31%, `BenchmarkBuffer/star/n=1024` -23%, `BenchmarkUnaryUnion/grid` sizes -23% to -26% — with time improvements of 2-5% on the star Intersection/Union/Difference benchmarks and -3.7% on Buffer, `UnaryUnion/grid` unchanged (within noise), and B/op essentially flat (+0.4% to +3.7%, geomean +1.6% — the residual slab headroom).
- **The noder→DCEL hand-off re-materialised every noded segment through two intermediate representations, and the indexed noders heap-allocated every output piece's coordinate slice individually.** Two independent copy-chain fixes, both byte-identical in output. First, the internal `taggedSegment` type and the exported `DepthSegment` type were the same 2-vertex-plus-payload record under two names, and `BuildDepthDCEL` bridged them by re-copying the caller's entire segment slice element-by-element before `buildDCELCore` would touch it; they are now one type (`DepthSegment`, carrying both the overlay `Tag` and the buffer `DepthDelta`), which `flattenNoded` (overlay) and `buildPolygonizeDCEL` (buffer) build directly and `buildDCELCore` consumes as-is — one intermediate representation between "noded strings" and the DCEL, zero re-copies. Second, `IndexedNoder.Node` and `MCIndexNoder.Node` (together 25.7% of a jagged-star intersection's alloc_space) emitted each output piece as its own `make([]geom.XY)`+`copy`; both now carve piece coordinate slices out of one flat per-`Node`-call arena slab, sized to an upper bound computed from counters already maintained during noding (total segments + 2× recorded candidate splits — no extra sizing pass), with overflow falling back to the old per-piece allocation (the same never-reallocate discipline as the DCEL's record slabs). Pieces occupy disjoint index ranges of the slab and are handed out as full 3-index slices (`cap == len`), so the in-place vertex mutations downstream code performs on its own noder output (`overlayng.snapNodedToGrid`, `snaprounding`'s `snapAndDedupe`) cannot cross a piece boundary, and an `append` past a piece's length reallocates instead of overwriting its slab neighbour. Outputs are byte-identical; JTS conformance held at 8942/8951. Allocations drop 8-15% on the star overlay ops (`BenchmarkIntersection/star/n=1024` -13.9%, `BenchmarkUnion/star/n=1024` -14.6%, `BenchmarkDifference/star/n=1024` -13.7%) and `BenchmarkBuffer/star/n=1024` improves on all three axes (-7.3% allocs, -2.4% B/op, -1.5% time); star-op time and B/op are flat (within the ±2.5% single-run noise band), and cascaded `UnaryUnion/grid` — whose many small builds route through the untouched `SimpleNoder` — is confirmed unchanged against a same-session control run.

## [1.0.0] - 2026-07-08

First stable release. Every exported symbol outside `internal/` is now covered by the v1 stability promise (see README "Versioning and stability"). The release is dominated by a pre-1.0 API-consistency sweep; the breaking changes below are the last of their kind before the SemVer contract takes effect.

### Changed (breaking)

- **`crs.CRS` is now immutable.** All fields are unexported; construct with `crs.New(authority, code, kind)`, `crs.NewWithDefinition(...)`, or `crs.NewFromWKT2(...)`, and read with the `Authority()`, `Code()`, `WKT2()`, `Kind()` accessors. The new `EPSG() (int, bool)` helper covers the common encoder idiom. The shared singletons (`crs.WGS84`, `epsg.Lookup(...)`, ...) can no longer be mutated — previously any caller could corrupt the process-wide registry.
- **`kernel/planar.Default`, `kernel/spherical.Default`, `kernel/geodesic.Default` are now functions** (`Default() kernel.Kernel`) instead of reassignable package vars.
- **`overlay/overlayng` moved to `internal/overlayng`.** The `overlay` package is the single public overlay entry point; `overlay.IntersectionGeneral` was unexported (`overlay.Intersection` already routes to it). The overlayng `*geom.Polygon`-typed API was never a stable-surface candidate.
- **`gts.ErrUnsupportedKernel` removed; `gts.ErrUnsupported` added.** The old sentinel was returned for unimplemented operations and unsupported input arity — nothing kernel-related. Sites in `overlay` and `buffer` now return errors wrapping `gts.ErrUnsupported` with the specific detail (match with `errors.Is`). `buffer.Buffer` on an unsupported type now wraps `ErrUnsupported` instead of misusing `ErrInvalidGeometry`.
- **`geom.ErrLayoutMismatch` added**; the `NewMulti*Strict` / `NewGeometryCollectionStrict` constructors wrap it so mixed-layout errors are matchable.
- **Java-ism renames**: `linearref.GetLength/GetLocation/GetLocationResolve` → `Length/Location/LocationResolve`; `linearref.LinearLocation.GetCoordinate` → `Coordinate`; `dissolve.LineDissolver` → `dissolve.Lines`; `quadedge.Subdivision.GetTriangleVertices/GetPrimaryEdges` → `TriangleVertices/PrimaryEdges`; `wkb.EncodeHex/DecodeHex` → `wkb.MarshalHex/UnmarshalHex`.
- **`geom.NewLinearRingFlatNoClone` → `geom.NewLinearRingOwned`**, aligning with `NewLineStringOwned`/`NewPolygonOwned`.
- **`quadedge.LocateFailureError` → `quadedge.ErrLocateFailure`** (idiomatic Go error naming).
- **`geom.XY.EqualOrBothNaN` removed** (was deprecated; `Equal` has identical NaN semantics).
- **Similarity measures moved from `measure` to `measure/match`.** `HausdorffSimilarity`, `AreaSimilarity`, `FrechetSimilarity`, `CombineSimilarities`, `CombineMin` now live in `measure/match` and call `overlay` directly. The `measure.IntersectionFunc`/`measure.UnionFunc` global hooks are gone — previously `AreaSimilarity` silently returned NaN unless `measure/match` was blank-imported.
- **`predicate.SetUnaryUnion` removed** (exported no-op stub).
- **`validate.FixOptions` unexported** (the `FixOption` functional options are the API, matching every other package's config-struct convention).
- **`geom.Edit` now preserves collection structure exactly**, including pre-existing empty children; previously it silently dropped them (also affected `gts.Transform` on collections).

### Added

- `geom.NewEmptyMultiPoint`, `NewEmptyMultiLineString`, `NewEmptyMultiPolygon`, `NewEmptyGeometryCollection` — layout-carrying empty constructors matching `NewEmptyPoint/LineString/Polygon`.
- The JTS conformance harness now enforces its baseline: `maxKnownDivergences` in `internal/jtstest/harness_test.go` (currently 9 of 8951) fails the suite on any regression, and CI runs it.
- `bench/` is its own Go module, keeping `simplefeatures` (and the rest of the harness graph) out of the library's dependency graph. The published module compiles zero third-party code into consumers.

### Fixed

- **WKB `POLYGON Z` corruption.** The encoder wrote XY-only ring vertices under a Z/M-flagged type code (corrupt stream); the decoder silently dropped Z/M from valid external polygons. Rings now encode/decode at full stride in both EWKB and ISO flavours.
- **`coverage.Simplify` was inert on shared boundaries and could corrupt rings.** A miscounted node rule marked every shared-chain interior vertex as a node, and chain-cache hits from the adjacent polygon were spliced without re-orienting. Shared boundaries now simplify in lockstep; the cache key encodes the full canonical vertex sequence.
- **`simplify.TopologyPreserving` now matches current JTS (PR #1024 port).** The section simplifier is a faithful port of `TaggedLineStringSimplifier`: the depth-based ring-minimum guard, segment (not infinite-line) distances, shared input/output segment sets, and the `simplifyRingEndpoint` pass. Closes JTS corpus cases TestSimplify #15/#16, which were previously misclassified as fixture drift.
- **`precision.Reduce` runs polygonal input through a snap-rounded self-union** (mirroring JTS `GeometryPrecisionReducer`'s overlay path) instead of pointwise ring snapping, so grid snapping that folds a ring into self-intersection is re-noded into valid faces. The conformance harness now exercises the real `precision.Reduce` (its private helper mishandled the JTS negative-scale-means-grid-size convention).
- `geom.Envelope` doc no longer claims the zero value is empty (it is a degenerate box at the origin; use `EmptyEnvelope()`).
- Stale package docs rewritten: `overlay/doc.go` (claimed only convex clipping worked; the full overlay-NG pipeline has shipped since Wave 20), `index/doc.go` (described one R-tree; eight index types ship, now with a per-type concurrency table), `kernel/doc.go` scaffolding language, `buffer.Buffer` doc ("polygon inputs are rejected" — they are supported).
- Import-order `gofmt` drift from the terra → go-topology-suite rename swept across 117 files.

### Internal consolidation (SLOC reduction, no API change)

Two review rounds reduced production source by ~3,400 lines (−8.4% overall) with `apidiff` verifying zero incompatible changes: duplicated geometry primitives consolidated into `internal/geomath`/`internal/xybuf`; the unreachable legacy Greiner-Hormann overlay engine removed (gated on corpus instrumentation); the boolean predicates collapsed onto the RelateNG engine (benchmarks within 3.2% of baseline; the hand-ported dispatch removed); snap-rounding hot-pixel corner tests upgraded to the robust planar kernel (matching JTS's DD arithmetic); encoder-internal dedupe verified byte-identical across a 665-output golden matrix. Conformance held at 8942/8951 throughout. A second round removed the duplicated buffer/overlayng DCEL substrate (gated on a byte-identical golden diff of all geometry-producing corpus outputs), deduplicated the conformance harness onto the library's own implementations (which exposed and fixed a UnaryUnion bug: LinearRing members of GeometryCollections were silently dropped), and removed dead buffer validators.

## [0.1.0] and the pre-v1 waves

go-topology-suite was developed over a series of waves driven by the JTS conformance harness and a parallel JTS-API parity sweep. Highlights:

- **Waves 1–6 (port build-out).** Geometry types, kernels, indexing, R-tree, snap-rounding, the OffsetSegmentGenerator buffer port, and the overlay-NG DCEL pipeline.
- **Waves 7–10 (RelateNG).** Lazy DE-9IM build pipeline ported in 104 commits; `RelateGeometry`, `TopologyComputer`, `RelateNode`, `EdgeSegmentIntersector`, and the surrounding edge/node infrastructure.
- **Wave 11–14 (API parity).** RectangleContains/Intersects, BufferDistance/ResultValidator, PolygonTriangulator, HausdorffSimilarity, AreaSimilarity, MinimumBoundingTriangle, VariableBuffer, KML writer, FrechetSimilarity, MortonCurve, CoveragePolygonValidator, CoverageCleaner, GeometryPrecisionReducer, CommonBits family, IteratedNoder, ScaledNoder, SegmentStringDissolver, SegmentIntersectionDetector, ValidatingNoder, BoundaryChainNoder.
- **Wave 15 (lift gates).** EnhancedPrecisionOp; GML2 reader/writer.
- **Wave 16 (RelateNG promotion).** Closed four RelateNG correctness bugs (point-on-segment robustness, zero-length-line vertex, Point shadowing, AB intersection node snapping); flipped `predicate.Relate` to RelateNG by default and removed the `UseLegacyRelate` opt-out.
- **Waves 17–19 (residual algorithmic gaps).** Closed `TestBufferExternal2 case#97` by reverting `OFFSET_SEGMENT_SEPARATION_FACTOR` to JTS pre-2023 (1e-3); diagnosed `GEOSBuffer#2`.
- **Wave 20 (LineString buffer rewrite).** Routed `bufferLineString` through the polygonizer pipeline (offset segments → snap-round → DCEL → per-subgraph depth labelling → kept-ring extraction → reduced-precision retry); zero algorithmic gaps remain.

The conformance baseline at v1.0.0 is **8 942 / 8 951 (99.90 %)**; the 9 residual failures are all rooted in JTS's own `failure/` corpus or externally tracked GEOS bugs, pinned as the harness baseline (see `internal/jtstest`).
